# Demo07Poker 斗地主洗牌发牌 — 流程梳理

## 核心数据结构

整个程序只有 3 层数据，搞清楚它们的关系就全通了：

```
  map (HashMap)              list (ArrayList)          p1/p2/p3/dipai
  ┌──────┬────────┐         ┌────────────────┐        ┌────────────┐
  │ key  │ 牌面   │         │ 打乱后的 key   │        │ 每人分到的 │
  │      │        │         │ 列表           │        │ key 列表   │
  ├──────┼────────┤         ├────────────────┤        ├────────────┤
  │  0   │  😊    │         │     35         │        │    35      │
  │  1   │  ☺     │         │      2         │        │     3      │
  │  2   │  ♠2    │         │      0         │        │    ...     │
  │  3   │  ♥2    │    →    │     17         │   →    └────────────┘
  │  4   │  ♣2    │         │     ...        │
  │ ...  │  ...   │         │     10         │
  │ 53   │  ♦A    │         │     53         │
  └──────┴────────┘         └────────────────┘
   字典：编号→名字           54个编号打乱顺序          每人拿到的编号
```

**一句话：`map` 是字典，`list` 是要洗的牌堆，`p1/p2/p3` 是每人摸到的牌。**

## 分步走

### 阶段一：造牌（建字典）

```
                                     map
花色 [♠, ♥, ♣, ♦]              key → 牌面
牌号 [2, 3, ..., A]             ─────────────
                               0 → 😊
双重循环 key=2 开始:            1 → ☺
                               2 → ♠2
  num=2, huase=♠ → key=2       3 → ♥2
  num=2, huase=♥ → key=3       4 → ♣2
  num=2, huase=♣ → key=4       5 → ♦2
  num=2, huase=♦ → key=5       6 → ♠3
  num=3, huase=♠ → key=6       ...
  ...                         53 → ♦A
```

给每张牌**编了个号**（0~53），号小的牌也小（0 最小 = 小王，53 最大 = ♦A）。

同时 `list` 里存了全部 54 个编号：`[0, 1, 2, 3, ..., 53]`

### 阶段二：洗牌

```java
Collections.shuffle(list);
```

**洗的是 `list`**，不是 `map`。`map` 永远是那个字典，一动不动。

```
洗之前 list: [0,  1,  2,  3,  4,  5,  ...  51,  52,  53]   ← 整整齐齐
洗之后 list: [35, 2,  0, 17, 50, 22, ...  10,  53,  8]     ← 乱七八糟
```

### 阶段三：发牌（按位置轮流摸）

**关键理解**：发牌的循环变量 `i` 是 `list` 的**位置下标**，不是牌本身！

```
     i=0      i=1      i=2      i=3      i=4      ...  i=51    i=52    i=53
list: [35,      2,       0,      17,      50,      ...   10,     53,      8]
       ↓       ↓        ↓        ↓        ↓              ↓       ↓       ↓
      玩家1    玩家2    玩家3     玩家1    玩家2    ...    底牌    底牌    底牌
```

每个 `i` 位置上的值 `list.get(i)` 才是**牌的编号**。用 `i` 的取模决定发给谁：

| i | i%3 | 归属 | list.get(i) 的值 |
|---|---|---|---|
| 0 | 0 | 玩家1 | 35 |
| 1 | 1 | 玩家2 | 2 |
| 2 | 2 | 玩家3 | 0 |
| 3 | 0 | 玩家1 | 17 |
| 4 | 1 | 玩家2 | 50 |
| ... | ... | ... | ... |
| 51 | — | 底牌 | 10 |
| 52 | — | 底牌 | 53 |
| 53 | — | 底牌 | 8 |

结果：

```
p1:    [35, 17, ...]   ← 17 个编号
p2:    [2,  50, ...]   ← 17 个
p3:    [0,  22, ...]   ← 17 个
dipai: [10, 53, 8]     ←  3 个
```

### 阶段四：理牌（排序）

```java
Collections.sort(p1);  // 按编号从小到大排
```

排序后：

```
排序前 p1: [35, 17, 1, 50, 3, ...]  ← 乱序
排序后 p1: [0,  3,  5, 12, 17, ...]  ← 小号在前，大号在后
```

因为编号本身就是按花色+牌号递增的（0 小王 < 1 大王 < 2 ♠2 < 3 ♥2 < ... < 53 ♦A），所以排序 = 自动理牌！

### 阶段五：看牌（编号 → 牌面）

```java
lookPoker("涛哥", p1, map);

// lookPoker 里做的事：
for (Integer key : list) {          // 遍历玩家的编号列表
    String value = map.get(key);    // 用编号去 map 里查出牌面
    System.out.print(value + " ");  // 打印
}
```

```
p1: [0, 3, 5, ...]
      ↓  ↓  ↓
map:  😊  ♥2 ♦2 ...

输出: 涛哥:😊 ♥2 ♦2 ...
```

## 完整数据流一览

```
① 造字典        ② 造牌堆        ③ 洗牌          ④ 发牌           ⑤ 理牌         ⑥ 看牌
                                                               (sort)        (map.get)
color[] ─┐    list = [0..53]  shuffle(list)   list 洗后顺序     p1.sort()
         ├→ map ──────────────────────────────────────────────────────────→ 查字典
number[]─┘    0→😊 1→☺         map 不动!      取 list.get(i)    编号从小到大  编号→牌面
              2→♠2 ...                       按 i 归属分人                    打印
              53→♦A
```

## 常见 Bug 对照

| Bug | 错误写法 | 正确写法 | 后果 |
|-----|---------|---------|------|
| 大小王 key 重复 | `map.put(0,"☺")` | `map.put(1,"☺")` | 大小王只剩一个 |
| 取了下标而非牌号 | `Integer key1 = i` | `Integer key1 = list.get(i)` | 洗牌完全失效 |
| 牌面挤在一起 | `value+""` | `value+" "` | 输出无法阅读 |

## 设计精髓

整个程序的核心思路是**操作编号不操作值**：

- 编号好排序（`Collections.sort` 天然有序）
- 编号占内存小（Integer vs String）
- 牌面与逻辑解耦（改显示只需要改 map）

这也是实际开发中 "数据与展示分离" 的体现。
