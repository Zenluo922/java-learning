# HashMap 底层原理详解

> 核心就三个东西：数组 + 链表 + 红黑树，搞懂这个就通了。

---

## 一句话理解

HashMap = 一个**数组**，每个位置挂了一串**链表**，链表太长就变**红黑树**

```
HashMap 底层结构 (JDK 8+)

数组 (table)
┌───┐
│ 0 │ → [key=张三, val=100] → [key=李四, val=200]   ← 链表（两个 key 撞到同一个位置）
├───┤
│ 1 │ → null                                        ← 这个位置空着
├───┤
│ 2 │ → [key=王五, val=300]                          ← 只有一个，没碰撞
├───┤
│ 3 │ → 🌲 红黑树（太多 key 撞到这里了）                ← 链表太长（≥8）变树
├───┤
│...│
└───┘
```

## 三个核心问题

### 问题一：数据存哪儿？

**存到数组里。** 数组查找快（O(1)），但问题：数组只能用下标（0, 1, 2...）访问，你给的可是任意 key 啊，怎么知道放哪个下标？

```java
map.put("apple", 5);   // "apple" 是字符串，怎么变成下标？
```

### 问题二：key 怎么变成下标？

**用 hashCode() + 取模运算。**

```
字符串 "apple"
    ↓ hashCode()
  一个整数，比如 93029210
    ↓ 取模 (hash & (数组长度-1))  
  下标，比如 2
    ↓
数组[2] = 存入数据
```

查的时候也一样：

```java
map.get("apple");
    → hashCode("apple") → 93029210
    → 93029210 % 16 = 2
    → 去数组[2] 找
```

### 问题三：两个 key 算出来同一个下标怎么办？（哈希碰撞）

**挂链表！**

```
"apple" → 下标 2
"banana" → 下标 2   ← 撞了！

数组[2]:
  [apple, 5] → [banana, 8] → null
                          
查 "banana" 时：
  1. 算下标 → 2
  2. 去数组[2] 遍历链表
  3. 用 equals() 比较每个节点的 key
  4. 找到 "banana" → 返回 8
```

## put 的完整流程

```
put(key, value)
    │
    ▼
key.hashCode()  →  算出哈希值
    │
    ▼
哈希值 & (数组长度-1)  →  得到数组下标
    │
    ▼
┌─ 数组[下标] 是空的吗？
│   YES → 直接放进去
│   NO  → 遍历这个位置的链表/树
│           ├─ 有相同的 key？（equals 判断）
│           │   YES → 覆盖旧值
│           │   NO  → 追加到链表末尾
│           └─ 链表长度 ≥ 8？
│               YES → 转成红黑树（查得快）
```

## get 的完整流程

```
get(key)
    │
    ▼
key.hashCode() → 哈希值 → 数组下标
    │
    ▼
数组[下标] 是null？
    YES → 返回 null（不存在）
    NO  → 遍历链表/树
           ├─ equals 匹配 → 返回 value
           └─ 都不匹配 → 返回 null
```

## 为什么 hashCode 和 equals 必须一起重写？

```java
class Student {
    String name;
    int age;
    // 如果只重写 equals，不重写 hashCode...
}
```

```
两个 Student 对象，内容完全一样（name="张三", age=20）

new Student("张三",20)  → hashCode() = 12345  → 下标 5
new Student("张三",20)  → hashCode() = 67890  → 下标 10

map.put(stu1, "优秀");   // 存到 数组[5]
map.get(stu2);           // 去 数组[10] 找 → 找不到！null！
```

**虽然 `equals` 说它俩相等，但因为 `hashCode` 不同，跑到了不同下标，HashMap 根本不会去比较。**

- `hashCode` 决定去哪个**下标**找（先定位）  
- `equals` 决定在那个位置的链表中找**哪个**节点（再比较）

## 扩容机制

```
初始: 数组长度 16         插入数据...
                            ↓
                      元素越来越多，链表越来越长
                            ↓
                      超过阈值（容量 × 0.75）
                            ↓
                      扩容！新数组 = 旧数组 × 2
                            ↓
                      所有旧数据重新计算下标搬家
```

关键参数：
- 初始容量 = 16
- 负载因子 = 0.75（75% 就扩容）
- 链表长度 ≥ 8 且数组长度 < 64 → 扩容
- 链表 ≥ 8 且数组 ≥ 64 → 转红黑树

## 一张图总结

```
                     HashMap
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   数组(table)      哈希碰撞处理       扩容机制
        │               │               │
   默认长度16      链表→红黑树(≥8)   超过75%翻倍
        │               │               │
   hashCode定位    equals比较        rehash搬家
```

**记住三个数字**：16（初始大小）、0.75（扩容阈值）、8（链表转树）
