### 2.3 通信三要素

```
┌──────────────────────────────────────┐
│          通信三要素                    │
├────────┬────────┬────────────────────┤
│ IP地址 │ 协议   │ 端口号              │
│ 找电脑 │ 怎么传 │ 找程序              │
├────────┼────────┼────────────────────┤
│127.0.0│TCP/UDP │ 0~65535             │
│.1     │        │ 0~1023=系统保留     │
│       │        │ 1024+=随便用        │
└────────┴────────┴────────────────────┘
```

#### IP 地址

- **IPv4**：`192.168.1.1` 格式，4 个字节，约 42 亿个
- **IPv6**：128 位，号称能给每粒沙子分配地址
- 本机地址：`127.0.0.1` 或 `localhost`（永远指向自己）
- 查看命令：`ipconfig`
- 测试连接：`ping 目标IP`

#### 端口号

- 范围 0~65535
- 0~1023：知名服务专用（如 80=HTTP、443=HTTPS）
- 普通程序用 **1024 以上**
- 端口被占用 → 程序启动失败

## 三、UDP vs TCP

```
UDP                           TCP
──────────────────────        ──────────────────────
无连接，直接发                先连接（三次握手），再通信
不管你收不收，照发不误         确认连接后才传数据
快，但不可靠                  慢，但可靠
DatagramSocket                Socket / ServerSocket
DatagramPacket                InputStream / OutputStream

类比：寄平信（不确认收没收到）  类比：打电话（通了才说话）
```

| | UDP | TCP |
|---|---|---|
| 连接 | 无连接 | 面向连接（三次握手） |
| 速度 | 快 | 慢 |
| 安全 | 可能丢包 | 保证送达 |
| 客户端 | DatagramSocket | Socket |
| 服务端 | DatagramSocket | ServerSocket + Socket |
| 发送 | socket.send(packet) | os.write(bytes) |
| 接收 | socket.receive(packet) | is.read(bytes) |

## 四、三次握手 & 四次挥手

### 三次握手（建立连接）

```
客户端                    服务端
   │                        │
   │───① 能连吗？──────────→│  第一次：客户端请求
   │                        │
   │←──② 收到，你来吧！─────│  第二次：服务端回应
   │                        │
   │───③ 好的我来了！──────→│  第三次：客户端确认
   │                        │
   ✅ 连接建立！开始传数据
```

> 就像打电话："喂？" → "听到了" → "好那我开始说了"

### 四次挥手（断开连接）

```
客户端                      服务端
   │                          │
   │───① 我发完了，准备走────→│  第一次：客户端说完了
   │                          │
   │←──② 等一下，最后的数据───│  第二次：服务端发最后数据
   │                          │
   │←──③ 我好了，可以断开了───│  第三次：服务端说可以断了
   │                          │
   │───④ 收到，拜拜！────────→│  第四次：客户端确认断开
   │                          │
   💔 连接断开
```

## 五、UDP 编程

### 核心类职责

```
DatagramSocket ≈ 快递公司（负责收发）
DatagramPacket ≈ 快递包裹（装着数据 + 收件地址）
```

### 发送端 4 步

```
1. new DatagramSocket()           → 开快递公司（随机端口）
2. new DatagramPacket(数据,长度,IP,端口) → 打包（指定收件地址）
3. socket.send(packet)            → 发出
4. socket.close()                 → 关门
```

### 接收端 4 步

```
1. new DatagramSocket(端口号)           → 开公司，指定门牌
2. new DatagramPacket(bytes, 长度)      → 准备空箱子
3. socket.receive(packet)               → 等快递（阻塞！）
4. 拆包裹：
   dp.getData()    → 数据
   dp.getLength()  → 实际长度 ← 重要！
   dp.getAddress() → 发件人IP
   dp.getPort()    → 发件人端口
```

### 「为什么 receive() 后要用 len，不能用 bytes.length？」

```
收到 "你好"（6 字节），bytes 长度 1024：

bytes = ['你','你','好','好','好','好', \0, \0, \0, ...]
         ← len=6 →←── 后面全是垃圾 ──────────→

❌ new String(bytes)           → "你好\0\0\0..."  垃圾也当字符串
✅ new String(bytes, 0, len)  → "你好"            只取有用部分
```

## 六、TCP 编程

### ServerSocket 和 Socket 的区别

```
ServerSocket ss          Socket socket
───────────────────      ───────────────────
只负责 accept() 等连接   负责和客户端真正通信
没有 getInputStream      有 getInputStream（读）✅
没有 getOutputStream     有 getOutputStream（写）✅
只有一个                   每 accept 一次产生一个
全程存活                  用完就关

类比：
ss    = 饭店门口迎宾员（只负责接客）
socket = 餐桌服务员（负责服务这一桌客人）
accept() = 迎宾员把客人领进来，分配一个服务员
```

### 客户端 4 步（Socket）

```
1. new Socket("127.0.0.1", 9999)   → 拨号连接
2. socket.getOutputStream()         → 获取发送流
   socket.getInputStream()          → 获取接收流
3. os.write(字符串.getBytes())      → 发送
   is.read(bytes)                   → 接收
4. 关流（先开后关）
```

### 服务端 5 步（ServerSocket → Socket）

```
1. new ServerSocket(9999)          → 开总机
2. Socket socket = ss.accept()     → 等人连接（阻塞！）
3. socket.getInputStream()         → 读流
   socket.getOutputStream()        → 写流
4. 读写数据...
5. 关流：os → is → socket → ss
```

## 七、文件上传

### 流程图

```
客户端                              服务端
─────                              ─────
1. FileInputStream 读本地文件
2. os.write() 发送数据  ──────────→ 3. is.read() 接收数据
   (while 循环边读边写)               (while 循环边读边写)
                                    4. FileOutputStream 存盘
5. shutdownOutput() ──────────────→ 6. is.read() 返回 -1（结束！）
7. is.read() 等响应  ←───────────── 8. os.write("上传成功")
```

### 关键：为什么必须 shutdownOutput()？

```
没有 shutdownOutput：
  客户端发完了 → 但没说"发完了"
  服务端 read() → 不知道发没发完 → 一直等 → 卡死 💀

有 shutdownOutput：
  客户端发完了 → 调 shutdownOutput() → "我发完了！"
  服务端 read() → 读到 -1 → 知道发完了 → 停止读取 ✅
```

### UUID 生成唯一文件名

```java
String uuid = UUID.randomUUID().toString();  // 随机十六进制串
String name = uuid + System.currentTimeMillis();  // 加上时间戳
// → "a1b2c3d4-e5f6-7890-abcd-ef12345678901725991234567.jpg"
// 保证不重名
```

## 八、多线程服务端

### 为什么需要多线程？

```
单线程：
  客户端A 连上 → 服务中... → A 断开
                              客户端B 连上 → 服务中... → B 断开
  一个完了才能下一个，排队！

多线程：
  客户端A 连上 → 开线程1 服务A
  客户端B 连上 → 开线程2 服务B    ← 同时服务！
  客户端C 连上 → 开线程3 服务C
```

### 核心代码结构

```java
ServerSocket ss = new ServerSocket(8888);

while (true) {                           // 主线程循环接客
    Socket socket = ss.accept();         // 等人来

    new Thread(() -> {                   // 子线程负责服务
        try {
            InputStream is = socket.getInputStream();
            // ... 读写操作 ...
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            // 关流！（每个流单独 try-catch）
        }
    }).start();                          // ← 别忘 start()！
}
```

### 主线程 vs 子线程

```
主线程（main）              子线程（Thread-0、Thread-1...）
───────────────────        ────────────────────────────────
只做一件事：                负责和客户端通信
  while(true) {             is.read() → 读消息
    accept() → 接客         处理...
    new Thread → 交给子线程   os.write() → 回复
  }                          关闭资源
```

## 九、常见错误速查表

| # | 错误 | 为什么错 | 正确做法 |
|---|------|----------|----------|
| 1 | `byte[].equals("字符串")` | byte[] 和 String 类型不同，永远 false | 先 `new String(bytes,0,len)` 再比 |
| 2 | `new String(bytes, 0, bytes.length)` | bytes.length=1024，取了 1024 个字符 | 用 `len`（read 返回值） |
| 3 | 文件上传服务端卡死 | 客户端没调 `shutdownOutput()` | 发完文件后调用 |
| 4 | 关流顺序：先关 socket | socket 关了，它身上的流也没了 | 反着开流顺序关：is→os→socket→ss |
| 5 | `new Thread` 没调 `.start()` | 只是创建了对象，没启动 | `.start()`！ |
| 6 | `sc.next()` 收不到空格 | next() 遇到空格就截断 | 用 `sc.nextLine()` |
| 7 | 先跑客户端再跑服务端 | 服务端还没开，客户端连谁？ | 先启动服务端再启动客户端 |
| 8 | 客户端判断 `响应.equals("886")` | 服务端返回的是反转后的字符串 | 判断自己发出去的原始字符串 |

## 十、类与方法速查

### UDP 相关

| 类/方法 | 作用 |
|---------|------|
| `new DatagramSocket()` | 创建 UDP 套接字（随机端口） |
| `new DatagramSocket(port)` | 创建 UDP 套接字（指定端口） |
| `new DatagramPacket(bytes, len, ip, port)` | 打包（发送用，指定地址） |
| `new DatagramPacket(bytes, len)` | 打包（接收用，空箱子） |
| `socket.send(dp)` | 发送数据包 |
| `socket.receive(dp)` | 接收数据包（阻塞） |
| `dp.getData()` | 获取包裹中的数据（byte[]） |
| `dp.getLength()` | 获取实际数据长度 |
| `dp.getAddress()` | 获取发送方 IP |
| `dp.getPort()` | 获取发送方端口 |

### TCP 相关

| 类/方法 | 作用 |
|---------|------|
| `new Socket(ip, port)` | 客户端连接服务端 |
| `new ServerSocket(port)` | 服务端监听端口 |
| `ss.accept()` | 等待客户端连接（阻塞，返回 Socket） |
| `socket.getOutputStream()` | 获取输出流（发数据） |
| `socket.getInputStream()` | 获取输入流（收数据） |
| `socket.shutdownOutput()` | 关闭输出流（发结束标记） |
| `os.write(bytes)` | 发送数据 |
| `is.read(bytes)` | 接收数据（返回实际读取字节数） |

### 辅助

| 类/方法 | 作用 |
|---------|------|
| `InetAddress.getByName(ip)` | 字符串 IP → InetAddress 对象 |
| `UUID.randomUUID().toString()` | 生成唯一随机字符串 |
| `new StringBuilder(s).reverse().toString()` | 反转字符串 |
| `System.currentTimeMillis()` | 当前时间戳 |
